# 验收记录

日期：2026-10-03。基准视口：375 × 667。浏览器：Playwright Chromium。数据快照：256 道真实菜谱（164 荤、92 素）。

| 要求 | 验证结果 |
| --- | --- |
| 一荤一素在一屏完整显示 | 通过。实测两张卡片的底边位于固定操作栏上方，无横向滚动。首页六个搭配入口也完整可见。 |
| 确认弹层列出菜名、食材数、时间 | 通过。浏览器读取菜单菜名并与弹层逐项核对。 |
| 清单合并、人数换算、刷新保留、纯文本复制 | 通过。规则测试验证同名用量加总和 2→4 人换算；浏览器验证勾选恢复及剪贴板内容。不同单位并列，未知用量明确显示。 |
| 一屏一步、滑动、倒计时、常亮 | 通过自动化。浏览器验证一步显示、Pointer Events 翻步、计时结束提示、振动调用和 Wake Lock 申请/释放。不支持 API 时静默降级；真实手机的物理振动、声音及系统后台行为仍需对应设备确认。 |
| 同桌不重菜、主料多样、遵守忌口 | 通过。200 次随机四道菜单验证无重复菜、无主料冲突、忌口/辣度/黑名单生效；单独验证候选不足和放宽顺序。 |
| 老乡鸡家庭份量与出处 | 通过。69 道补充库菜谱逐道验证 2 人份、主料合计 250–400g、克数为 5 的倍数。保留原名及供应商、原文链接和单独的家庭替代建议。 |
| 荤素各至少 30 道真实菜 | 通过。164 道荤菜、92 道素菜；只来自指定两个仓库。134 个未可靠解析或非配菜条目记录跳过原因。 |
| 无登录打开、添加桌面、离线 | 本地生产包通过。验证 manifest、192/512 图标、standalone 模式、service worker 控制和离线刷新后读取完整菜谱与今日菜单。实际部署状态见 README 的在线地址；手机添加桌面需使用浏览器系统菜单。 |

## 数据边界

- 原文没写精确用量时不补数；无法可靠换算主料的老乡鸡菜谱不进入成品库。
- 用时和部分元数据为关键词规则估算，原文有明确时间时优先采用。
- 商用复合调味料的家庭替代只是单独的建议，不声称能复刻门店风味。
- 图片通过 jsDelivr 加载；离线未缓存图片时使用菜名首字占位，菜谱文字可以离线阅读。
